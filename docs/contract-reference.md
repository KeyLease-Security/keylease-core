# Contract reference

`KeyLeaseRegistry` — the Soroban escrow and accounting contract for KeyLease.
This page is generated by hand from `contracts/registry/src/`; treat the source
as authoritative.

- **Package:** `keylease-registry`
- **Wasm:** `target/wasm32v1-none/release/keylease_registry.wasm`
- **Network target:** Stellar (`wasm32v1-none`), `soroban-sdk 26`
- **Constants:** `SETTLE_GRACE_PERIOD_SECS = 86_400` (24 hours),
  `MAX_LEASE_DURATION_SECS = 2_592_000` (30 days),
  `MAX_LEASE_DEPOSIT = 1_000_000_000_000` base units (100,000 of a
  seven-decimal token such as XLM)
- **Storage TTL:** `LEDGER_BUMP_THRESHOLD = 17_280`, `LEDGER_BUMP_EXTEND = 518_400`,
  `MAX_ENTRY_TTL_LEDGERS = 1_555_200` (90 days); leases extend to term + 24h
  grace + a 1-day buffer, clamped to `MAX_ENTRY_TTL_LEDGERS` and to the network's
  live `maxEntryTtl`. Only writes and the two `bump_*` entry points extend a TTL;
  reads never do.
- **On-chain metadata:** `name = KeyLeaseRegistry`, `version`,
  `eventSchemaVersion`, `description`, `repository`, embedded with `contractmeta!`

Every state-changing entry point calls `require_auth()` on the actor it
represents. Errors are returned as `Result<_, Error>`; codes are stable and never
renumbered. Every money-moving path persists its effect before calling the SEP-41
token (checks-effects-interactions).

## Administration

### `init`

```rust
pub fn init(env: Env, admin: Address) -> Result<(), Error>
```

Initialize the registry and appoint `admin`.

- **Caller / auth:** `admin` must authorize.
- **Trigger:** once, immediately after deploy.
- **Preconditions:** the registry must not already be initialized.
- **State:** sets `Admin`; extends instance TTL.
- **Events:** `registry_initialized { admin }`.
- **Errors:** `AlreadyInitialized`.
- **Notes:** the admin can only call `set_token` and `upgrade`. It cannot move
  user funds.

### `set_token`

```rust
pub fn set_token(env: Env, admin: Address, token: Address) -> Result<(), Error>
```

Point the registry at the SEP-41 token used for every deposit and payout.

- **Caller / auth:** `admin`, and `admin` must match the stored admin.
- **Trigger:** once at setup; again only to migrate the escrow asset.
- **State:** sets `Token`; extends instance TTL.
- **Events:** `escrow_token_set { admin, token }` — only when the token actually
  changes.
- **Errors:** `NotInitialized`, `Unauthorized`.
- **Notes:** the native Stellar Asset Contract (SAC) is the usual value. Changing
  the token while leases are unsettled is a migration hazard — settle first.
- **Idempotent:** calling `set_token` with the token that is already configured
  returns `Ok(())` and does nothing — no storage write, no TTL extension and no
  event — so a repeated call cannot be mistaken for a migration. Auth and the
  stored-admin check still run first, so an unauthorized caller receives
  `Unauthorized` either way.

### `upgrade`

```rust
pub fn upgrade(env: Env, admin: Address, new_wasm_hash: BytesN<32>) -> Result<(), Error>
```

Install a new registry Wasm through the Soroban deployer.

- **Caller / auth:** `admin`, and `admin` must match the stored admin.
- **Trigger:** a released bug fix or feature, after uploading the Wasm with
  `stellar contract upload`.
- **Effects:** `env.deployer().update_current_contract_wasm(new_wasm_hash)`.
- **Events:** `contract_upgraded { admin, new_wasm_hash }`.
- **Errors:** `NotInitialized`, `Unauthorized`.
- **Notes:** the contract id, storage and balances are preserved, so an upgrade
  must never change the `DataKey` layout or the meaning of stored values. See
  [Deployment](deployment.md#upgrading).

## Services

### `register_service`

```rust
pub fn register_service(
    env: Env,
    provider: Address,
    rate_per_call: i128,
    endpoint_hash: BytesN<32>,
) -> Result<u64, Error>
```

Publish a new leasable service.

- **Caller / auth:** `provider` must authorize.
- **Trigger:** when a provider lists an API or RPC endpoint.
- **Parameters:**
  - `rate_per_call` — price per metered call in token stroops; must be `> 0`.
  - `endpoint_hash` — 32-byte commitment to the off-chain descriptor.
- **Returns:** the new `service_id` (monotonic, starts at `1`).
- **State:** writes `Service(service_id)`, increments `ServiceCount`, extends
  instance TTL.
- **Events:** `service_registered { service_id, provider, rate_per_call, endpoint_hash }`.
- **Errors:** `InvalidRate`, `Overflow`.

### `set_service_active`

```rust
pub fn set_service_active(
    env: Env,
    provider: Address,
    service_id: u64,
    is_active: bool,
) -> Result<(), Error>
```

Pause or resume **new** leases for a service.

- **Caller / auth:** `provider`, and it must own the service.
- **Trigger:** maintenance, incident response, or retirement.
- **State:** updates `Service(service_id).is_active`.
- **Events:** `service_status_changed { service_id, provider, is_active }`.
- **Errors:** `ServiceNotFound`, `Unauthorized`.
- **Notes:** existing leases stay valid and settleable. Deactivation only blocks
  `create_lease`.

## Leases

### `create_lease`

```rust
pub fn create_lease(
    env: Env,
    consumer: Address,
    service_id: u64,
    requested_calls: u32,
    duration_secs: u64,
) -> Result<u64, Error>
```

Lock a deposit and mint a time-bound lease.

- **Caller / auth:** `consumer` must authorize.
- **Trigger:** a developer purchases metered access.
- **Preconditions:** `requested_calls > 0`, `0 < duration_secs ≤
  MAX_LEASE_DURATION_SECS`, `rate_per_call × requested_calls ≤
  MAX_LEASE_DEPOSIT`, the service exists and `is_active`, and `Token` is
  set.
- **Effects:** `transfer(consumer → contract, rate_per_call × requested_calls)`.
- **Returns:** the new `lease_id` (monotonic, starts at `1`).
- **State:** writes `Lease(lease_id)` with `expires_at = ledger.timestamp() +
  duration_secs` and a TTL covering the term plus grace; increments `LeaseCount`.
- **Events:** `lease_created { lease_id, service_id, consumer, allocated_calls, expires_at, locked_deposit }`.
- **Errors:** `InvalidCalls`, `InvalidDuration`, `DurationTooLong`,
  `ServiceNotFound`, `ServiceInactive`, `InvalidRate`, `TokenNotSet`, `Overflow`,
  `DepositTooLarge`.

The deposit is bounded twice, and the two rejections mean different things.
`Overflow` says `rate_per_call × requested_calls` does not fit `i128`.
`DepositTooLarge` says it fits and is still more than one lease may lock. The
bound is checked after the multiplication and before the lease id is allocated
or the token is called, so a rejected lease moves nothing and consumes no id.

### `settle_lease`

```rust
pub fn settle_lease(
    env: Env,
    provider: Address,
    lease_id: u64,
    verified_calls: u32,
) -> Result<(), Error>
```

Propose a settlement and open the consumer challenge window. No funds move yet.

- **Caller / auth:** `provider`, and it must own the lease's service.
- **Trigger:** at or after expiry, or as soon as every allocated call is consumed.
- **Preconditions:** lease exists, is not settled, `verified_calls ≤
  allocated_calls`, the caller owns the service, and the lease has expired **or**
  `verified_calls == allocated_calls`.
- **Effects:** persists `used_calls` and `settled = true`, then writes a
  `Settlement(lease_id)` entry with `state = Pending`,
  `payout = verified_calls × rate_per_call`, `refund = locked_deposit − payout`
  and `challengeable_until = now + CHALLENGE_WINDOW_SECS`. No token transfer
  happens.
- **Events:** `lease_settlement_proposed { lease_id, provider, verified_calls,
  payout, refund, challengeable_until }`.
- **Errors:** `LeaseNotFound`, `LeaseAlreadySettled`, `InvalidCalls`,
  `Unauthorized`, `LeaseNotSettleable`, `Overflow`.
- **Notes:** the lease can no longer be settled again or revoked once a proposal
  exists. The payout stays locked until the challenge window closes and
  `finalize_settlement` (or `resolve_challenge`) releases it. Settling with
  `verified_calls = 0` proposes a full consumer refund.

### `finalize_settlement`

```rust
pub fn finalize_settlement(env: Env, lease_id: u64) -> Result<(), Error>
```

Release a pending proposal once its challenge window has closed.

- **Caller / auth:** none — permissionless. The provider, consumer or any keeper
  can finalize.
- **Preconditions:** a settlement exists, `state == Pending`, and
  `now ≥ challengeable_until`.
- **Effects:** persists `state = Finalized`, then calls
  `transfer(contract → provider, payout)` and
  `transfer(contract → consumer, refund)` (zero-value transfers are skipped).
- **Events:** `lease_settled { lease_id, provider, verified_calls, payout, refund }`.
- **Errors:** `SettlementNotFound`, `SettlementFinalized`,
  `SettlementChallenged`, `ChallengeWindowStillOpen`, `TokenNotSet`.
- **Notes:** `lease_settled` is now only emitted when funds actually move.

### `challenge_settlement`

```rust
pub fn challenge_settlement(
    env: Env,
    consumer: Address,
    lease_id: u64,
    evidence_hash: BytesN<32>,
) -> Result<(), Error>
```

Dispute a proposed settlement inside the challenge window.

- **Caller / auth:** the lease's `consumer` must authorize.
- **Preconditions:** a settlement exists, is `Pending` (not already challenged
  or finalized), `now < challengeable_until`, and `evidence_hash` is not all
  zeroes.
- **Effects:** stores `challenge_evidence` and `challenged_at`; sets
  `state = Challenged`. Funds remain locked.
- **Events:** `lease_challenged { lease_id, consumer, evidence_hash }`.
- **Errors:** `SettlementNotFound`, `SettlementFinalized`,
  `SettlementChallenged`, `ChallengeWindowClosed`, `InvalidEvidence`,
  `Unauthorized`.
- **Notes:** the evidence itself stays off chain; only its 32-byte commitment is
  stored. The admin resolves the dispute.

### `cancel_challenge`

```rust
pub fn cancel_challenge(env: Env, consumer: Address, lease_id: u64) -> Result<(), Error>
```

Withdraw an active challenge and return the settlement to `Pending`.

- **Caller / auth:** the lease's `consumer` must authorize.
- **Preconditions:** a settlement exists, `state == Challenged`.
- **Effects:** clears the evidence fields and sets `state = Pending`. The
  original `challengeable_until` is unchanged.
- **Events:** `lease_challenge_cancelled { lease_id, consumer }`.
- **Errors:** `SettlementNotFound`, `SettlementFinalized`,
  `NoActiveChallenge`, `Unauthorized`.
- **Notes:** cancellation does not pay out early and does not extend the window.
  While the window is still open the consumer may challenge again.

### `resolve_challenge`

```rust
pub fn resolve_challenge(
    env: Env,
    admin: Address,
    lease_id: u64,
    upheld: bool,
) -> Result<(), Error>
```

Decide an active challenge. Admin only.

- **Caller / auth:** the stored `admin` must authorize.
- **Preconditions:** a settlement exists and `state == Challenged`.
- **Effects:** persists `state = Finalized`, then pays the outcome:
  - `upheld = true` — `payout = 0`, `refund = locked_deposit` (full consumer
    refund),
  - `upheld = false` — the proposal's payout and refund stand.
- **Events:** `lease_challenge_resolved { lease_id, admin, upheld }` followed by
  `lease_settled { lease_id, provider, verified_calls, payout, refund }`.
- **Errors:** `SettlementNotFound`, `SettlementFinalized`,
  `NoActiveChallenge`, `NotInitialized`, `Unauthorized`, `TokenNotSet`,
  `Overflow`.
- **Notes:** resolution may happen before or after the window closes. The admin
  can only choose between the proposal and a full refund; it cannot redirect
  funds elsewhere.

### `revoke_expired_lease`

```rust
pub fn revoke_expired_lease(
    env: Env,
    consumer: Address,
    lease_id: u64,
) -> Result<(), Error>
```

Reclaim the **full** deposit when the provider never settled.

- **Caller / auth:** `consumer`, and it must be the lease's consumer.
- **Trigger:** after `expires_at + SETTLE_GRACE_PERIOD_SECS`.
- **Effects:** persists `settled = true` first, then
  `transfer(contract → consumer, locked_deposit)`.
- **Events:** `lease_revoked { lease_id, consumer, refund }`.
- **Errors:** `LeaseNotFound`, `Unauthorized`, `LeaseAlreadySettled`,
  `LeaseNotExpired`, `RevokeWindowNotElapsed`, `TokenNotSet`, `Overflow`.
- **Notes:** this is the consumer's escape hatch, and the reason escrow is safe
  against an unresponsive provider. It is unavailable once a settlement has been
  proposed: the lease is marked settled at proposal time and the challenge
  window is the consumer's remedy from then on.

## Storage maintenance

Reads no longer keep entries alive, so extending a lifetime is an explicit,
metered call of its own. Both entry points are permissionless: the caller pays
for the extension with their own transaction fee, and the horizon comes from the
contract's policy rather than from the caller.

### `bump_service`

```rust
pub fn bump_service(env: Env, service_id: u64) -> Result<(), Error>
```

Extend a service entry to `LEDGER_BUMP_EXTEND` ledgers.

- **Caller / auth:** anyone.
- **Errors:** `ServiceNotFound` — a miss is an error, not a silent no-op, so a
  caller never pays for an extension that kept nothing alive.
- **Notes:** `create_lease` extends the service it leases from, so an actively
  used service does not need this. It exists for a published-but-idle service.

### `bump_lease`

```rust
pub fn bump_lease(env: Env, lease_id: u64) -> Result<(), Error>
```

Extend a lease entry using the lease TTL policy (remaining term + 24h grace + a
1-day buffer, clamped to `MAX_ENTRY_TTL_LEDGERS` and the network's
`maxEntryTtl`).

- **Caller / auth:** anyone.
- **Errors:** `LeaseNotFound`, `LeaseAlreadySettled`.
- **Notes:** the extension can only raise the entry's lifetime, never lower it,
  and stops once the remaining term is exhausted: a long-expired lease is bumped
  by about two days at a time, not by its original term. A settled lease is
  rejected because its funds have already moved.

## `LeaseStatus` and the `settled` flag

`LeaseStatus::of` (`contracts/registry/src/types.rs`) reads exactly two fields:

```rust
if lease.settled { LeaseStatus::Settled }
else if now >= lease.expires_at { LeaseStatus::Expired }
else { LeaseStatus::Active }
```

`settled` is the **escrow-release flag**, not the reason the funds left.
`settle_lease` sets it after a provider payout, and `revoke_expired_lease` sets
it after a full refund, so both terminal paths report `Settled` (discriminant
`2`) and `lease_status` cannot tell them apart. The same collapse shows up in the
error: `LeaseAlreadySettled` (`7`) means "already settled **or** revoked".

### Telling the two paths apart

`used_calls` is written by `settle_lease` only — `revoke_expired_lease` never
touches it — so for most leases one read separates the paths:

| Signal after `settled == true` | Meaning |
| --- | --- |
| `used_calls > 0` | `settle_lease` paid the provider for that many calls. |
| `used_calls == 0` | **ambiguous**: a revoke, or a settle reported with `verified_calls = 0`. |
| `lease_revoked` exists for this `lease_id` | the consumer reclaimed the deposit. |
| `lease_settled` exists for this `lease_id` | the provider settled; read `payout`/`refund`. |

The ambiguity is real and not an edge case: a provider that could not serve a
lease at all settles it with `verified_calls = 0`, which refunds the whole
deposit and leaves `used_calls` at `0` — a storage state identical to a
revocation. Only the published event distinguishes the two, so anything that
reports provider reliability or revenue **must** consume the event stream rather
than poll `get_lease`: see
[Topics, payloads and filters](integration.md#topics-payloads-and-filters).

### Status by lifecycle event

Worked terms: `rate_per_call = 1_000_000`, `allocated_calls = 500`,
`duration_secs = 3600`, so `locked_deposit = 500_000_000`.

| Lifecycle point | `settled` | `used_calls` | `lease_status` | `remaining_calls` | `locked_balance` |
| --- | --- | --- | --- | --- | --- |
| `create_lease` | `false` | `0` | `Active` | `500` | `500_000_000` |
| 120 calls served, not yet expired | `false` | `0` | `Active` | `500` | `500_000_000` |
| `settle_lease(320)` before expiry | *rejected* — `LeaseNotSettleable` | `0` | `Active` | `500` | `500_000_000` |
| expiry reached, nobody acted | `false` | `0` | `Expired` | `0` | `500_000_000` |
| `settle_lease(320)` inside the 24h grace | `true` | `320` | `Settled` | `0` | `0` |
| `settle_lease(500)` (all calls used) | `true` | `500` | `Settled` | `0` | `0` |
| `settle_lease(0)` inside the 24h grace | `true` | `0` | `Settled` | `0` | `0` |
| `revoke_expired_lease` after the grace | `true` | `0` | `Settled` | `0` | `0` |

Two things to read off that table:

- `used_calls` and `remaining_calls` describe the **settled** allotment, not live
  usage. Providers report call counts at settlement, so mid-term rows keep
  `used_calls = 0`; per-request enforcement is the provider's own counter,
  bounded on chain by `allocated_calls` (see
  [the verification pipeline](integration.md#the-verification-pipeline)).
- The last four rows are indistinguishable by `lease_status` alone. Distinguish
  them by `used_calls`, then by the event, never by the status code.

## Read-only views

These require no authorization, and none of them extends a TTL. An extension
bills the caller for rent across the whole extended horizon, so a "view" that
performed one could not be used to price a read.

| View | Signature | Returns |
| --- | --- | --- |
| `get_admin` | `(env) -> Result<Address, Error>` | stored admin, else `NotInitialized` |
| `get_token` | `(env) -> Result<Address, Error>` | escrow token, else `TokenNotSet` |
| `version` | `(env) -> String` | version embedded by `contractmeta!` |
| `service_count` | `(env) -> u64` | total services ever registered |
| `lease_count` | `(env) -> u64` | total leases ever created |
| `get_service` | `(env, service_id: u64) -> Result<Service, Error>` | the `Service`, else `ServiceNotFound` |
| `get_lease` | `(env, lease_id: u64) -> Result<Lease, Error>` | the `Lease`, else `LeaseNotFound` |
| `lease_status` | `(env, lease_id: u64) -> Result<LeaseStatus, Error>` | derived status at current ledger time |
| `remaining_calls` | `(env, lease_id: u64) -> Result<u32, Error>` | calls left; `0` once settled **or** expired |
| `locked_balance` | `(env, lease_id: u64) -> Result<i128, Error>` | `locked_deposit`; stays at `locked_deposit` while a settlement is pending or challenged; `0` once finalized or revoked |
| `get_settlement` | `(env, lease_id: u64) -> Result<Settlement, Error>` | the `Settlement`, else `SettlementNotFound` |

> `remaining_calls` returns `0` as soon as the lease expires, even if calls were
> never consumed. A caller that wants the raw allotment should read
> `get_lease().allocated_calls`.

## Events

Events are part of the ABI. Each event name is a `Symbol` topic, followed by the
`#[topic]` fields; the payload is a map keyed by field name.

Every payload carries `schema_version` (`EVENT_SCHEMA_VERSION`, currently `1`) as
its first map key. Topics are frozen: a version is never added as a topic,
because topics are positional and indexers filter on them.

| Event | Topics | Payload fields |
| --- | --- | --- |
| `registry_initialized` | — | `schema_version`, `admin` |
| `escrow_token_set` | — | `schema_version`, `admin`, `token` |
| `service_registered` | `service_id` | `schema_version`, `provider`, `rate_per_call`, `endpoint_hash` |
| `service_status_changed` | `service_id` | `schema_version`, `provider`, `is_active` |
| `lease_created` | `lease_id` | `schema_version`, `service_id`, `consumer`, `allocated_calls`, `expires_at`, `locked_deposit` |
| `lease_settled` | `lease_id` | `schema_version`, `provider`, `verified_calls`, `payout`, `refund` |
| `lease_revoked` | `lease_id` | `schema_version`, `consumer`, `refund` |
| `contract_upgraded` | — | `schema_version`, `admin`, `new_wasm_hash` |

See [integration.md](./integration.md#event-schema-version) for how to branch on
the version.

```bash
stellar events --id $REGISTRY --network testnet --start-ledger 123456
```

```rust
pub enum DataKey {

    Token,        // instance
```

## Error codes

Codes are part of the ABI. New variants are **appended**; existing numbers are
never reused.

| Code | Variant | Meaning |
| --- | --- | --- |
| 1 | `AlreadyInitialized` | `init` called twice |
| 2 | `NotInitialized` | registry has no admin |
| 3 | `Unauthorized` | caller is not the required actor |
| 4 | `ServiceNotFound` | no service with that id |
| 5 | `ServiceInactive` | service is paused |
| 6 | `LeaseNotFound` | no lease with that id |
| 7 | `LeaseAlreadySettled` | lease already settled or revoked |
| 8 | `LeaseNotSettleable` | not expired and not fully consumed |
| 9 | `LeaseNotExpired` | `revoke` before expiry |
| 10 | `RevokeWindowNotElapsed` | `revoke` inside the 24h grace window |
| 11 | `InvalidCalls` | zero calls, or more than allocated |
| 12 | `InvalidDuration` | zero duration |
| 13 | `InvalidRate` | non-positive rate |
| 14 | `TokenNotSet` | escrow token not configured |
| 15 | `Overflow` | checked arithmetic failed |
| 16 | `DurationTooLong` | lease duration above `MAX_LEASE_DURATION_SECS` |
| 17 | `DepositTooLarge` | deposit above `MAX_LEASE_DEPOSIT` |

## Invoking with the Stellar CLI

```bash
# register a service
stellar contract invoke --id $REGISTRY --source-account provider --network testnet \
  -- register_service \
     --provider $PROVIDER \
     --rate_per_call 1000000 \
     --endpoint_hash 0707070707070707070707070707070707070707070707070707070707070707

# create a lease
stellar contract invoke --id $REGISTRY --source-account consumer --network testnet \
  -- create_lease \
     --consumer $CONSUMER \
     --service_id 1 \
     --requested_calls 500 \
     --duration_secs 3600

# propose a settlement
stellar contract invoke --id $REGISTRY --source-account provider --network testnet \
  -- settle_lease --provider $PROVIDER --lease_id 1 --verified_calls 320

# finalize after the 24h challenge window (anyone may call this)
stellar contract invoke --id $REGISTRY --source-account provider --network testnet \
  -- finalize_settlement --lease_id 1

# the consumer can dispute inside the window
stellar contract invoke --id $REGISTRY --source-account consumer --network testnet \
  -- challenge_settlement --consumer $CONSUMER --lease_id 1 --evidence_hash <64_HEX_CHARS>

# the admin resolves the dispute
stellar contract invoke --id $REGISTRY --source-account admin --network testnet \
  -- resolve_challenge --admin $ADMIN --lease_id 1 --upheld true

# upgrade (after `stellar contract upload`)
stellar contract invoke --id $REGISTRY --source-account admin --network testnet \
  -- upgrade --admin $ADMIN --new_wasm_hash <64_HEX_CHARS>
```

## MockToken (test only)

`contracts/mock_token` implements a minimal SEP-41 surface — `init`, `mint`,
`transfer`, `transfer_from`, `approve`, `allowance`, `balance`, `decimals` (7),
`name`, `symbol`, `admin` — with an **unlimited mint**.

It exists so local sandboxes do not depend on a live SAC, but it must **never**
be deployed to a network holding value. The registry's own tests escrow against
the real Stellar Asset Contract (`register_stellar_asset_contract_v2`).
