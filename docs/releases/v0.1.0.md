# keylease-core v0.1.0

**First public release of the KeyLease registry contract.**

KeyLease replaces long-lived static API/RPC credentials with **time-bound,
on-chain micro-leases**: a consumer locks a micropayment in Soroban escrow and
receives an authorization the provider can verify cheaply, with an automatic
refund path if the provider goes offline.

## Highlights

- **Escrowed micro-leases.** `create_lease` locks
  `rate_per_call × requested_calls` in a SEP-41 token and mints a lease that
  expires at `ledger.timestamp() + duration_secs`.
- **Provider settlement.** `settle_lease` pays the provider for verified calls
  and refunds the remainder to the consumer. Settleable once the lease expires
  or once every allocated call is consumed.
- **Guaranteed consumer exit.** `revoke_expired_lease` reclaims the **full**
  deposit 24 hours after expiry if the provider never settled — no support
  ticket required.
- **Service registry.** Providers publish a rate and an `endpoint_hash`
  commitment instead of a secret, and can pause new leases.
- **Checked arithmetic throughout.** Deposit and payout math aborts on overflow
  rather than truncating into a cheaper lease or a short refund.

## Error codes

`Error` variants 1–15 are part of the ABI and will never be renumbered. See the
[contract reference](../contract-reference.md#error-codes).

## Compatibility

- Rust `1.84+`
- `soroban-sdk` `26`
- Wasm target `wasm32v1-none`

## Known limitations

- **Not audited.** Pre-1.0 software. Do not escrow mainnet value you would be
  unhappy to lose.
- **Trusted token assumption.** The registry assumes the SEP-41 token set by the
  admin behaves. Re-entrancy hardening of the money paths is tracked as a
  `wave-high` issue.
- **No events emitted yet.** Observability is tracked as a `wave-medium` issue.
- **No provider-side CLI.** Providers register services with
  `stellar contract invoke` until `@keylease/cli` ships a `register` command.
