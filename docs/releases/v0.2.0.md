# keylease-core v0.2.0

**Soroban-native hardening: events, upgrades, storage-safe leases and
re-entrancy protection.**

This release moves the protocol closer to the Stellar primitives it depends on.
The escrow model and the public lease lifecycle are unchanged, but the contract
is now observable, upgradeable and hardened against hostile SEP-41 tokens.

## Highlights

- **Typed Soroban events.** Every transition publishes a `#[contractevent]`:
  `registry_initialized`, `escrow_token_set`, `service_registered`,
  `service_status_changed`, `lease_created`, `lease_settled`, `lease_revoked`
  and `contract_upgraded`. Topics carry `service_id` / `lease_id`, so the
  lifecycle is indexable without polling storage.
- **On-chain metadata.** `contractmeta!` embeds the name, version, description
  and repository in the Wasm, and `version()` returns the running version.
- **In-place upgrades.** `upgrade(admin, new_wasm_hash)` installs a new Wasm
  through the Soroban deployer, preserving the contract id, storage and
  balances. Admin-only, and it emits `contract_upgraded`.
- **Checks-effects-interactions.** `settle_lease` and `revoke_expired_lease`
  persist `settled = true` **before** calling the token. A new adversarial test
  installs a re-entrant token that calls back into `settle_lease` and asserts the
  second attempt is rejected.
- **TTL-safe lease durations.** `create_lease` rejects durations above
  `MAX_LEASE_DURATION_SECS` (30 days) with the new `DurationTooLong` (16) error,
  and lease storage is extended for the term plus the 24h grace window. Escrow
  can no longer outlive its ledger entry.
- **Real SAC coverage.** The suite now escrows through
  `register_stellar_asset_contract_v2` — the same Stellar Asset Contract that
  wraps native XLM — in addition to the mock token.

## Compatibility

- Rust `1.84+`
- `soroban-sdk` `26`
- Wasm target `wasm32v1-none`
- Error codes 1–16 are part of the ABI and will never be renumbered.

### Upgrading from v0.1.0

- Existing storage keys, error codes 1–15 and lease semantics are unchanged, so
  a v0.2.0 Wasm can be installed over a v0.1.0 deployment with `upgrade`.
- New restriction: `duration_secs` above 30 days now reverts with
  `DurationTooLong`. Existing longer leases are unaffected and remain settleable.
- New entry point and events are additive.
- Set the escrow token with the native SAC and confirm `version()` afterwards.

## Known limitations

- **Not audited.** Pre-1.0 software. Do not escrow mainnet value you would be
  unhappy to lose.
- **Upgrade trust.** The admin can replace the Wasm; use a cold or multisig
  Stellar account for the admin role.
- **No provider key rotation or rate update yet.** Both are `wave-medium`
  issues.
- **Settlement trusts the provider's call count**, bounded by the on-chain
  allotment and the consumer refund path.
