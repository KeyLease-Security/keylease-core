# keylease-core v0.2.1

**Rent-aware lease storage.** A Testnet deployment showed that extending every
lease to the generic thirty-day horizon made Soroban storage rent dominate short
leases: creating a 100-call, one-hour lease cost more in rent than the deposit
itself. This release pays only for the storage time a lease can actually be used.

## What changed

- **Lease TTL is term-aware.** `save_lease` and `get_lease` extend a lease entry
  to `(expires_at − now + 24h) / 5s + LEDGER_BUMP_THRESHOLD` ledgers: the lease's
  remaining term, the provider's 24-hour grace window and a one-day read buffer.
- **No more month-long padding.** A one-hour lease no longer rents thirty days of
  storage; the host still enforces its minimum persistent TTL (~7 days on
  Testnet), but the unnecessary padding is gone. A 30-day lease still gets the
  full term plus grace and buffer, under the network's maximum entry TTL.
- **Reads use the same policy.** `get_lease` no longer bumps to a fixed thirty-day
  horizon, so a read near expiry does not silently pay a month of rent.
- **Verified on Testnet.** `CCEZYHUJ…TAFH62` runs this build; two leases were
  created, fully settled and partially settled on-chain. See
  [Deployments](../deployments.md).

## Compatibility

- No ABI, event, storage-key or error-code changes. v0.2.0 deployments can be
  upgraded in place with `upgrade`.
- Rust `1.84+`, `soroban-sdk` 26, `wasm32v1-none`.
- `version()` returns `0.2.1`.
